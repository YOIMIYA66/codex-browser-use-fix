# 26.901 依赖漂移、物化失败残留与备份清理

本文记录一次 Codex Desktop 更新后的完整依赖修复，供下一次 AppX 更新后快速判断。示例路径均使用 `%USERPROFILE%` 等占位符，不包含机器凭据或个人配置内容。

## 结论

Desktop 更新成功并不代表用户侧 `openai-bundled` marketplace 和已安装插件已经同步。26.901 这次故障中，AppX 已是新版本，Desktop/CUA runtime 也已自动物化，但稳定 marketplace 仍停留在上一版，导致 Browser、Chrome、Computer Use 的安装记录过期。

修复应按“检查 → 备份 → 暂存 → 哈希校验 → 原子切换 → 一次性重装 → 复核”的顺序完成；不要把一次性恢复改造成后台同步任务。

| Desktop AppX | `26.901.6511.0` | unchanged |
| AppX bundled Browser/Chrome/Computer Use | `26.901.51231` | `26.901.51231` |

健康检查最终返回 `HEALTH_EXIT=0`；runtime 检查返回 `RUNTIME_WHATIF_EXIT=0`。`Current AppX managed: False` 只是因为当前保留的是稳定兼容路径；只要其中的 manifest 与当前 AppX 一致，就不是版本漂移错误。

## 根因与边界

AppX、runtime marketplace、已安装插件缓存和全局 CLI 是不同层。AppX 更新后，Desktop 的自动物化机制可能没有刷新手工保留的稳定目录；runtime 自身仍可能健康。因此不能只看 Desktop 版本号，也不能用全局 PATH 中的 `codex --version` 推断 Desktop runtime 是否正确。

Chrome 集成不在本次验收范围：没有修改 Chrome 扩展、Native Host 注册表/manifest、Secure Preferences 或 `chrome\\latest`，也没有做真实 Chrome 导航测试。为保持 marketplace 版本表一致，Chrome 插件包可以随 bundled 插件一起更新，但这不等于启用或验证 Chrome 集成。

## 经验证的恢复顺序

1. 运行仓库中的只读健康检查，记录 AppX、package marketplace、active marketplace、runtime manifest 和 installed plugin 的版本。
2. 备份 `%USERPROFILE%\\.codex\\config.toml`、当前 marketplace 和 bundled plugin cache。
3. 从当前 AppX 的 `app\\resources\\plugins\\openai-bundled` 复制到唯一暂存目录；使用 `robocopy /XJ /COPY:DAT /DCOPY:DAT /A-:E`，避免 junction 递归和 EFS 属性传播。
4. 对源目录和暂存目录逐文件比较相对路径、数量和 SHA-256，并确认暂存文件没有加密属性。
5. 将旧稳定目录移到带时间戳的 `pre-repair` 回滚目录，再把已校验的暂存目录原子落位为稳定 `openai-bundled`。
6. 只对当前启用的 bundled 插件执行一次 `codex plugin add <name>@openai-bundled --json`；不要注册计划任务，也不要反复清空 cache。
7. 再次运行健康检查和 Desktop runtime smoke test。若 runtime 已为 healthy，不要覆盖它。

## 失败物化残留的识别与清理

本次发现 19 个目录，名称均为 `openai-bundled.staging-<GUID>`，全部创建于较早日期、`0` 文件、`0` 字节，且当前配置没有引用。这类目录可判定为失败物化残留。

清理前必须确认：

- 目标是 marketplace 根目录的直接子目录；
- 名称严格匹配 staging 模式；
- 不是 reparse point/junction；
- 没有文件；
- 最近没有写入活动。

成功快照（`openai-bundled-appx-*`）、`pre-repair-*` 回滚点和配置备份不是失败残留，不应按名称一并删除。

## 备份保留策略

本次将 17 个明确重复或已被后续版本覆盖的备份目录移入 Windows 回收站，共 11,096 个文件、约 `0.98 GiB`：

- 重复/过期的 skill、Chrome UI 和 Desktop ownership 快照；
- 旧 marketplace/bootstrap/first-run 试验；
- 2026-08-24 至 2026-09-04 的旧完整 dependency 快照；
- 早期仅含 `config.toml` 的 dependency 快照。

保留边界：最新两份完整 dependency 回滚备份、三份 conversation/state 数据库快照、Windows Store 策略备份，以及根目录 SQLite 快照。回收站中的目录仍可恢复，不能把“移入回收站”误报成已清空磁盘。

## 下一次 Desktop 更新后的快速路径

```text
1. 完全退出并重新打开 Codex Desktop
2. 运行 check-codex-browser-health.ps1
3. 比较 package/runtime/installed 三组插件版本
4. 版本一致：不修改任何东西
5. 版本不一致：备份、暂存、SHA-256、原子切换、一次性 plugin add、复核
6. 只清理已确认的空 staging 残留
```

官方自动物化应优先使用，但当前机器上不能假定每次 AppX 更新都会完成注册和缓存重协调；稳定兼容路径也不应被误认为官方自动同步。全局 CLI、Desktop runtime 与插件 marketplace 各自独立，修复 Desktop 时不要顺便修改 PATH 或全局 CLI。
